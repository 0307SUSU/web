#### 什么是堆？什么是栈？它们之间有什么区别和联系？

> ### 堆（Heap）：
>
> - **定义**：堆是一种动态分配内存的区域，用于存储引用类型（对象）的数据。
> - **特点**：堆内存的分配和释放不是按照顺序的，而是通过程序员手动分配和释放，或者由垃圾回收机制自动回收。
> - **适用场景**：适合存储动态大小的数据，例如对象、数组等。
> - **存储方式**：存储的是引用类型的数据，实际数据保存在堆中，而栈中保存的是指向堆中数据的指针。
>
> ### 栈（Stack）：
>
> - **定义**：栈是一种先进后出（FILO）的数据结构，用于存储基本数据类型和对象的引用。
> - **特点**：栈内存的分配和释放是自动的，由编译器或解释器控制，例如函数调用时的局部变量。
> - **适用场景**：适合存储固定大小的数据，例如基本数据类型和对象的引用。
> - **存储方式**：存储的是基本数据类型的值和对象的引用，实际数据保存在栈中。
>
> ### 区别和联系：
>
> - **分配方式**：堆内存需要手动或自动管理，而栈内存是自动管理。
> - **分配效率**：堆内存的分配和释放比栈内存更慢。
> - **存储内容**：堆存储引用类型数据的实际内容，而栈存储基本数据类型的值和对象的引用。
> - **生命周期**：堆内存的生命周期由程序员或垃圾回收器控制，而栈内存的生命周期与函数调用相关。
> - **空间大小**：堆内存一般比栈内存大，并且不会因为函数调用结束而释放。
>
> ### 在 JavaScript 中的应用：
>
> - **堆**：用于存储对象（如普通对象、数组、函数等），通过引用来访问。
> - **栈**：用于存储基本数据类型的值和对象的引用。在函数调用时，会创建一个函数执行上下文（函数栈帧），其中包含函数的参数、局部变量等信息。函数执行完毕后，栈帧被销毁，释放相应的内存空间。

>

>
>    ```js
>    javascript

>

#### JavaScript 原型，原型链？ 有什么特点？

> 每个对象都包含一个prototype对象，这个对象被称为原型，获取原型的方法object.getPrototypeOf(),往原型对象上添加属性的方法object.setPrototypeOf()
>
> 原型链是由每个对象中的原型对象构成的一个树状结构，原型链有一个顶端Object.prototype,一般在查找对象的属性或方法时如果当前对象中不存在就会去原型对象上找，一直根据原型链的树状结构往上查找直到找到或者查到原型链的顶端还没有找到的话就会返回undefined；

#### 为什么原型链的顶端是Object.prototype

> 1. **Object 是所有对象的基类**：在 JavaScript 中，所有对象都是 `Object` 的实例，包括函数、数组等。因此，`Object.prototype` 上定义的属性和方法可以被所有对象共享和继承。
> 2. **Object.prototype 是原型链的终点**：在原型链的顶端是 `Object.prototype`，因为它是原型链的终点。`Object.prototype` 的 `__proto__` 属性为 `null`，表示它没有原型，是原型链的最终链接。
> 3. **Object.prototype 上定义了通用的方法和属性**：`Object.prototype` 上定义了一些通用的方法和属性，比如 `toString()`、`valueOf()` 等，这些方法和属性可以被所有对象继承和使用。

#### <font style="font-size:18px;font-weight:600;">事件冒泡与事件捕获原理</font>

事件冒泡（Event Bubbling）和事件捕获（Event Capturing）是描述事件传播方式的两种机制。

事件捕获从最外层祖先元素向目标元素传播，

而事件冒泡则相反，从目标元素向最外层祖先元素传播。

在实际开发中，我们更多地使用事件冒泡来处理事件，因为这样可以更方便地实现事件委托和更好地控制事件流程。

使用 e.stopPropagation()来阻止事件冒泡。作用当然是阻止我们触发它上级的事件啦

#### <font style="font-size:18px;font-weight:600;">call、apply、bind的区别</font>

共同点：

- 都是用来改变函数的this对象的指向的
- 第一个参数都是this要指向的对象
- 都可以参加后续参数传参

不同点：

- bind是返回对应函数，便于稍后调用；apply、call则是立即调用
- apply和call功能一样，只是传入的参数列表形式不同，call 需要把参数按顺序传递进去，而 apply 则是把参数放在数组、伪数组里。

#### <font style="font-size:18px;font-weight:600;">什么是闭包，为什么要用它？</font>

一个作用域可以访问另外一个函数内部的局部变量，或者说一个函数（子函数）访问另一个函数（父函数）中的变量。此时就有闭包产生，那么这个变量所在的函数我们就称之为闭包函数。

优缺点：闭包的主要作用是延伸了变量的作用范围，因为闭包函数中的局部变量不会等着闭包函数执行完成就销毁，因为还有别的函数需要调用它，只有等这所有的函数都调用完了它才会被销毁。

如何解决：用完之后手动释放。

#### <font style="font-size:18px;font-weight:600;">内存泄漏</font>

内存泄漏指的是我们用动态存储分配的函数来开辟空间，但是在使用完了没有释放，结果就一直占据该内存单元，直到程序结束。简而言之就是用完了还没回收这就是内存泄漏。

1. **意外的全局变量**：在全局作用域中声明的变量如果没有及时释放，会导致对象一直存在于内存中，无法被垃圾回收。
2. **循环引用**：两个对象互相引用，且都不再被使用，但由于彼此之间仍然存在引用关系，导致无法被垃圾回收。
3. **定时器和事件监听器未清理**：定时器和事件监听器如果没有被及时清理，会导致对象一直存在于内存中，无法被释放。
4. **DOM 引用未清理**：如果某个元素被从 DOM 树中移除，但仍然被引用着，会导致该元素无法被垃圾回收。
5. **闭包**：闭包中的函数引用了外部函数的变量，导致外部函数的变量无法被释放，从而造成内存泄漏。

为了避免内存泄漏，可以采取以下几个方法：

- 避免创建不必要的全局变量。
- 注意及时清理不再使用的对象引用。
- 避免循环引用。
- 在使用定时器和事件监听器时，确保在不需要时及时清理。
- 在使用闭包时，注意内存占用情况，避免不必要的引用。

#### **说说从输入 URL 到看到页面发生的全过程**

当用户在浏览器中输入 URL 后，浏览器首先进行 DNS 解析，将域名解析成 IP 地址，

然后通过 TCP 协议与服务器建立连接。

接着，浏览器向服务器发起 HTTP 请求，服务器接收到请求后处理并返回响应。

浏览器接收到响应后，开始解析 HTML 和 CSS，构建 DOM 树和渲染树，最终将页面内容渲染到用户的屏幕上。

整个过程包括 DNS 解析、建立 TCP 连接、发起 HTTP 请求、服务器处理响应、浏览器解析响应、构建 DOM 树和渲染页面等步骤。

#### 浏览器缓存

> 强缓存、协商缓存，
>
> 强缓存通过设置响应头实现，可以直接查询加载资源，无需向服务器发送请求
>
> 协商缓存通过设置请求头和响应头实现，至少需要向服务器发送一次请求，服务器根据请求判断并返回资源
>
> 一般情况下浏览器会先查询是否存在强缓存，如果存在直接从本地缓存中加载资源，如果不存在则向服务器发送请求验证协商缓存
>
> 1. 常用的请求头有：
>    - `If-Modified-Since`：表示资源的最后修改时间，服务器会根据这个时间判断资源是否有更新。
>    - `If-None-Match`：表示资源的唯一标识符（通常是一个 hash 值），服务器会根据这个标识符判断资源是否有更新。
>
> 协商缓存的响应头有：
>
> - `Last-Modified`：表示资源的最后修改时间。
> - `ETag`：表示资源的唯一标识符。
>
> 常见的强缓存响应头
>
> - `Expires`：指定资源的过期时间，是一个绝对时间，即到了指定时间后资源过期。
>
> - ```
>   Cache-Control
>   ```
>
>   ：用于控制缓存的行为，常见的值有：
>
>   - `public`：表示响应可以被任何中间缓存（如CDN）缓存。
>   - `private`：表示响应只能被浏览器缓存，中间缓存不能缓存。
>   - `max-age=<seconds>`：指定资源在本地缓存中的最大存储时间，单位为秒。

#### 浏览器存储数据方式

SessionStorage、LocalStorage 和 Cookie 都是浏览器端存储数据的方式，它们有一些区别：

- `SessionStorage` 数据存储在浏览器的会话中，会话结束时数据被清除；`LocalStorage` 数据永久存储在浏览器中，除非手动清除；`Cookie` 可以设置过期时间，也可以在同一站点的不同页面之间共享。
- `SessionStorage` 和 `LocalStorage` 通常支持的容量比 `Cookie` 大得多，一般为 5MB 左右；`Cookie` 的容量限制为 4KB。
- `Cookie` 会在每次 HTTP 请求时发送到服务器，可以用于与服务器通信；`SessionStorage` 和 `LocalStorage` 仅在客户端存储，不会自动发送到服务器。
- `SessionStorage`、`LocalStorage` 和 `Cookie` 的 API 使用方式有所不同，但都提供了类似的操作方法。
- `Cookie` 可以设置安全标志和 HttpOnly 标志，提高安全性；`SessionStorage` 和 `LocalStorage` 存储的数据相对不太安全，容易受到 XSS 攻击。

#### **说说 ajax、fetch、axios 之间的区别**

> Ajax 是一种使用 JavaScript 发起异步 HTTP 请求的技术，可以使用原生的 XMLHttpRequest 对象或者各种库来实现。
>
> Fetch 是一种现代的 JavaScript API，用于发起网络请求，基于 Promise 实现，更现代化和方便。
>
> Axios 是一个基于 Promise 的 HTTP 客户端，提供了更多功能和友好的 API，可以用在浏览器和 Node.js 环境中。
>
> Fetch 是浏览器原生提供的 API，Axios 则是一个功能丰富的第三方库。

#### Promise（承诺）

*Promise 是ES6引入的异步编程的新解决方案。比传统的解决方案（回调函数）更加合理和更加强大*

- **状态**：pending（进行时）、fulfilled（已成功）、rejected（已失败）
- **用法：** Promise 对象是一个构造函数，会接受一个函数作为参数，这个函数的两个参数分别是 `resolve`和`reject`
  - `resolve` 函数的作用是将 **Promise** 对象的状态从 “未完成” 变为 “成功”
  - `reject` 函数的作用是将 **Promise** 对象的状态从 “未完成” 变为 “失败”

```
const promise = new Promise(function(resolve, reject) {});
```

- **实例方法：**

  - then() ---- 实例状态发生变化时，触发的回调函数，第一个参数是 `resolved`状态的回调函数，第二个参数是 `rejected` 的回调函数（一般使用 catch 方法来替代第二个参数）
  - catch() ---- 用于指定发生错误的回调函数
  - finally() --- 用于指定 不管 Promise 对象最后状态如何，都会执行的操作

  链式调用

  Promise 的链式调用是指在一个 Promise 的回调函数中返回一个新的 Promise，从而实现对多个异步操作的依次执行和处理。

#### 前端大文件下载暂停如何实现

1. **使用`XMLHttpRequest`或`fetch` API进行文件下载**：首先，使用`XMLHttpRequest`或`fetch` API从服务器下载大文件。这将返回一个可读取的文件流。
2. **分段下载文件**：为了实现暂停功能，可以将文件分成多个部分进行下载。每次下载一个部分，然后将这些部分拼接起来。
3. **暂停下载**：在下载过程中，可以通过中断下载请求（`XMLHttpRequest.abort()`或`fetch` API的`AbortController`）来暂停下载。记录已下载的部分内容和当前下载进度。
4. **继续下载**：在暂停后，用户要求继续下载时，可以根据已下载的部分内容和当前下载进度，发送新的下载请求，继续下载剩余部分的文件。

#### https与http

> HTTPS（Hyper Text Transfer Protocol Secure）和 HTTP（Hyper Text Transfer Protocol）之间的主要区别在于安全性。HTTPS 使用 SSL/TLS 协议对传输的数据进行加密，确保数据在传输过程中不被窃取或篡改，同时也提供了服务器身份验证和数据完整性保护。相比之下，HTTP 不对数据进行加密，容易被窃取和篡改，也没有身份验证机制，存在被中间人攻击的风险。因此，在需要保护数据安全和隐私的情况下，推荐使用 HTTPS。
